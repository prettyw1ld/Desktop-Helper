# Подсветка и обучение: как перенести изменения на Windows

## Что уже общее для обеих систем

`src/renderer/app.js` отвечает за кота, жёлтую рамку и размещение инструкции. Здесь нет отдельной реализации интерфейса для Mac: исправления положения подсказки и переноса кота уже применяются и на Windows.

- `placeBubble()` вычисляет положение по текущим координатам кота и фактической высоте карточки. Вызывается после перемещения кота в каждом кадре. Выбор «сверху / снизу» пересчитывается заново: старое положение снизу нельзя сохранять после прыжка к нижнему краю.
- Размеры берутся через `offsetWidth / offsetHeight`: анимация появления не должна влиять на расчёт границ. Карточка ограничена рабочей областью окна приложения; длинная инструкция прокручивается.
- Отпускание перенесённого кота во время обучения переводит его в `perch`, без падения и без `endGuide()`. Это намеренная фиксация в выбранном месте, а не завершение шага.
- Во время перетаскивания сценарий не опрашивает условия перехода и не запускает новый прыжок. После отпускания `resumeCoachAfterDrag()` восстанавливает текущую инструкцию. Следующий шаг или явный повтор снова могут переместить кота к нужной кнопке.

`src/renderer/coach.js` управляет последовательностью шагов. `showRing()` и `goPoint()` получают уже готовые координаты. Поиск может задержаться при открытии окна, поэтому отсутствие элемента в первом ответе не означает ошибку: опрос повторяется, сообщение об отсутствии появляется после нескольких попыток. Ошибки разрешений отличаются от отсутствия элемента.

## Где проходят границы между системами

| Часть | macOS | Windows |
|---|---|---|
| Поиск элементов и окон | `src/native/locator.swift`, резервный JXA в `src/locate.js` | PowerShell UI Automation в `src/locate.js` |
| Сценарии | Массив `mac` в `src/renderer/scenarios.js` | Нужен отдельный массив `win` для обучения файлам |
| Открытие учебной папки | `src/files.js`, Electron `shell.openPath()` | Тот же код: системные пути берутся из Electron |
| Папки, кнопки и их имена | Finder, русские и английские имена | Проводник, свои имена и типы UI Automation |
| Определение текущей папки | `check({filePlace: ...})` сейчас читает первое настоящее окно Finder | Пока не реализовано; нельзя просто оставить проверку Finder |

## Контракт поиска

Главный процесс принимает запросы через `api.locate()`. Пример запроса учебного сценария на Mac:

```js
{ op: 'find', scope: 'proc:^Finder$', firstWindow: true,
  name: 'Мои открытки', types: ['ListItem'] }
```

Ответ содержит `items`, каждый с `x`, `y`, `w`, `h`, `name`, `type`, `focused`, `enabled`, `proc`; сведения об окне находятся в `win`. Ошибка приходит как `error`, а не как выдуманный элемент с координатами.

Экранные координаты нормализует `toOverlayRect()` в `src/main.js`: у Windows физические пиксели переводятся в DIP, затем вычитается начало рабочей области. На Mac Accessibility уже возвращает точки. Renderer не должен повторно учитывать масштаб экрана: иначе рамка съедет при масштабе Windows 125–150%.

Не выбирать безусловно первый объект в списке окон. На Mac перед настоящим Finder встречается служебное окно показа экрана размером 52×20. Нативный поиск отбрасывает маленькие, безымянные и свёрнутые окна. Для Windows тоже нужно проверить, что выбран именно Проводник, а не служебная поверхность.

Типы элементов различаются: в Finder с видом «список» имя файла оказалось `AXTextField`, поэтому оно включено в набор `ListItem`. Не копировать это имя типа в Windows: там используются типы UI Automation, уже перечисленные в сценариях (`ListItem`, `DataItem`, `TreeItem` и т. д.). Подбирать их по реальному дереву Проводника.

## Что потребуется для обучения файлам на Windows

1. Добавить `win`-шаги для `files-learn` и `files-downloads`, с реальными названиями кнопок Проводника. Начинать обучение с «Мои открытки»: папка уже открывается приложением, вводный шаг с «Загрузками» удалён.
2. Реализовать чтение выбранного окна Проводника независимо от окна Пушика. Запрос `op: 'window'` сейчас реализован для Mac; диспетчер PowerShell пока знает только `find`, `top`, `drives`.
3. Дополнить `check({filePlace: ...})` для Windows. Проверять текущую папку по данным Проводника; один факт появления папки среди элементов не означает, что человек вошёл в неё. Учитывать несколько окон и одинаковые названия папок.
4. Убрать ограничение Mac в `startFileLesson()` только после готовности этих частей. Само меню и открытие документов уже общие.
5. Проверить целиком: открыть папку → вернуться → открыть письмо → вернуться в Проводник → включить поиск → найти файл. Отдельно проверить вид «список» и «значки», масштаб Windows, прыжки к верхнему и нижнему краю, перенос кота и остановку обучения.

## Проверки

`node --test tools/test-file-help.js`

В том числе проверяются сохранение сценария при переносе кота, пауза переходов во время переноса, появление рамки и прыжка после задержанного ответа, а также размещение карточки у разных краёв экрана. Эти проверки не заменяют проход по настоящему интерфейсу ОС. Для последней правки дополнительно проверен перенос кота вверх и в нижний угол в браузерном предпросмотре с сохранением первого шага.
